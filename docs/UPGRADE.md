# Обновление TrueNAS CORE 13.3 до bsdnas на FreeBSD 15

Документ описывает то, что проверено на стенде, а не то, что предполагается.
Каждое утверждение здесь получено измерением; там, где проверка не проводилась,
это сказано прямо.

## Что проверено

Официальный образ iX `TrueNAS-13.3-U1.2` установлен на тестовую машину, настроен
(пул-зеркало, датасет, SMB-шара, джейл iocage) и обновлён образом bsdnas
на базе FreeBSD stable/15.

Результат:

| проверка | результат |
|---|---|
| система поднимается | да, `state: READY` |
| конфигурация сохраняется | пулы, шары, пользователи, пароль — на месте |
| пул, созданный OpenZFS 2.2 | импортируется и работает на 2.4.3 |
| датасеты | на месте |
| SMB-шара из 13.3 | работает, `enabled` |
| джейл iocage с userland 13.3 | запускается на ядре 15, данные целы |

За один шаг меняются: FreeBSD 13.3 → stable/15, OpenZFS 2.2 → 2.4.3,
Samba 4.20 → 4.23, Python в портах 3.9 → 3.11, поколение схемы конфигурации.

Полный цикл обновления на стенде занимает около 15 минут.

## Порядок обновления

1. **Сделайте резервную копию конфигурации** через веб-интерфейс
   (System → General → Save Config). Это отдельный файл, он не зависит от
   состояния загрузочного устройства.
2. Загрузитесь с образа bsdnas.
3. `Install/Upgrade` → выберите загрузочное устройство → **`Upgrade Install`**.
4. `Install in new boot environment` — новая загрузочная среда создаётся рядом
   со старой, прежняя остаётся в списке и доступна для отката через меню
   загрузчика.
5. Дождитесь окончания, извлеките носитель, загрузитесь с диска.

Первая загрузка дольше обычной: идут миграции конфигурационной базы. На стенде
система отвечала через 60–90 секунд после появления консольного меню.

## Про `zpool upgrade` — читайте до, а не после

После обновления система сообщит, что для пула доступны новые фичи. **Не спешите.**

Что установлено проверкой:

* Сразу после `zpool upgrade` пул **остаётся импортируемым** старой OpenZFS 2.2.
  Проверено: установщик 13.3 видит обновлённый пул как `ONLINE` и предлагает
  импорт с `-f`, без единого замечания о несовместимости.
* Причина: `zpool upgrade` переводит фичи в состояние `enabled`, но не `active`.
  Сразу после операции активных фич — ноль.
* Доступ старой системе закрывается, когда любая новая фича становится `active`,
  то есть когда её начинают реально использовать: дедупликация, длинные имена,
  расширение raidz и подобное.
* **Переход в активное состояние происходит побочным эффектом обычной работы
  и никак не анонсируется.**

Практический вывод: окно отката после `zpool upgrade` существует, но закрывается
молча, и полагаться на него нельзя.

Разумный порядок:

1. обновить систему;
2. убедиться, что всё работает — шары, задания, джейлы;
3. пожить так столько, сколько нужно для уверенности;
4. и только потом делать `zpool upgrade`, сознательно расставаясь с возможностью
   вернуться на 13.3.

Загрузочный пул (`boot-pool`) обновлять отдельно не требуется.

## Джейлы

Джейлы с userland FreeBSD 13 работают на ядре 15: в конфигурации ядра включены
`COMPAT_FREEBSD13` и `COMPAT_FREEBSD14`. Проверено — джейл `13.3-RELEASE-p8`
после обновления стартует, команды внутри исполняются, файлы целы.

Отдельно стоит знать: **ветка FreeBSD 13.x убрана с основного зеркала**
(`download.freebsd.org` отдаёт 404 на 13.3 и 13.5). На системе, оставшейся
на 13.3, новый джейл штатным путём уже не создать — iocage не находит релиз.
Существующие продолжают работать. Обходной путь для 13.3 — архивный сервер:

```
iocage fetch -r 13.3-RELEASE -s archive.freebsd.org -d old-releases/amd64
```

Это одна из причин, по которой оставаться на 13.3 неудобно: платформа
функционально заморожена.

## Известные шероховатости

* **Служба SSH после обновления не поднимается сама** — включите её заново
  в веб-интерфейсе или через API.
* Индекс плагинов iocage от iX больше не обновляется; плагины ставятся только
  из собственного индекса либо вручную.
* Аппаратные RAID-утилиты `arcconf`, `megacli`, `tw_cli` в сборку не входят:
  их дистрибутивы исчезли и у вендоров, и в `distcache.FreeBSD.org`.
  Для NAS на ZFS аппаратный RAID и так противопоказан.

## Что не проверялось

Честный список того, на что этот документ не отвечает:

* обновление с версий старше 13.3 (13.0, 12.x, 11.x);
* системы с HA (двухконтроллерные), шифрованием GELI, iSCSI под нагрузкой,
  доменной аутентификацией;
* пулы с raidz, кэшем и логами на отдельных устройствах — проверялось зеркало;
* поведение под реальной нагрузкой и на объёмах больше стендовых.
